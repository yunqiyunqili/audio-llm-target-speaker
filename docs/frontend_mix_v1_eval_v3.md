# frontend_mix_v1 评估 v3：方向估计前做极性修正（frontend-mix-v1-eval-v3；2026-11-05；规则在计算前写定，看到结果后不修改）

> **注意**：这个修正是在看过 mix_v1 的结果（FaSNet-TAC 第 0 路极性相反，见 `docs/c4_v1.md`）之后才提出的，所以它在 mix_v1 上的结果**可能偏乐观**。cv_dev93 上的核查没有参与修正的设计，作为外部检查。

## 范围
- 只用现有的 `data/mix_v1/separated_v1/` 输出，**不重跑 mix_v1 的前端**。不跑 C5，不加入新前端，不写方向匹配 v4。不修改 mix_v1、已有结果或 v1/v2 的判定。
- 主要评估 FaSNet-TAC；BLSTM+MVDR 用同一规则，只作对照。

## 极性修正规则（不用参考信号，不写死输出路编号）
- 对每个样本的每一路输出 y_k，计算它与 mic 0 观测的零延迟相关 c_k = Σ_t y_k(t) · x_0(t)。c_k < 0 就把 y_k 取反，否则不变。
- 方向估计的其余部分与 v1/v2 完全相同（`eval_frontend_mix_v1.doa`）：取让 |wrap(θ̂_k − θ1)| 最小的一路，**方向相同时取第 0 路**。
- 准确率用 **direct 参考匹配**（v2 的 `ref_stream_direct`）作为标准。SI-SDR 不受符号影响，所以参考匹配不需要重算。

## 判定（门槛不变）
- 只用夹角不在 [0,15) 的 150 个样本计算方向匹配准确率：≥ 0.85 时，该前端在 v3 下可以进入 C5；否则不进 C5。[0,15) 只报告。阈值是经验值。
- 本轮不进入 C5。即使 v3 判为可以进入，也只记录这个判定。

## mix_v1 上报告的内容
- 方向匹配准确率（全部 200 个，以及不含 [0,15) 的 150 个）和失败样本；
- 分层（夹角、T60、有效重叠比例、完整 image SIR）；
- 两路的方向误差：目标路与 θ1 比，干扰路与 θ2 比；另外按输出路编号报告；
- 极性修正的比例：按输出路编号分别统计取反的比例，以及修正后与 direct 参考的相关是否为正。

## 外部核查：SMS-WSJ cv_dev93 的 50 组官方混合
- 50 组用 `random.Random(2026).sample(sorted(cv_dev93 ids), 50)` 抽取，与 frontend_sanity_v1 的 B、C 相同。
- 这次需要在 cv_dev93 上**重新运行**两个前端：在 CPU 节点上用 srun，推理代码与 frontend_mix_v1 相同；输出只在内存中，不写音频。mix_v1 的前端输出不重跑。
- 每组产生 2 个"目标样本"：目标是声源 0 时，θ_t = 声源 0 的 az_rel；目标是声源 1 时同理。参考匹配用官方 direct 参考做 PIT。
- 报告：
  - 两路与各自 direct 参考的零延迟相关，分输出路编号统计；
  - 是否同样存在极性翻转（相关 < 0 的比例）；
  - 修正前和修正后的方向匹配准确率（全部，以及不含 [0,15)）。
- cv_dev93 的结果不改变 mix_v1 的判定。
