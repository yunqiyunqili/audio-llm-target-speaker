## 1. 依据（已有结果）
- C1/P2 0.694，Whisper + T2 0.653，C0（标准转写 + T2）0.782，均为 124 条 devel 录音、按录音（`c0_plan_v1.md`）。
- c1-error-taxonomy-v1：三种输入下未命中实体中漏抽都占约 48–59%（C0 的 27 个漏抽中 15 个是 date），边界 / 类型不一致约 18 个；去掉"听"只消除了"听错"一类。
- 因此 LoRA 的增益可能主要来自学习 SLURP 的实体标注范围，这部分对文本路线同样适用。主要比较必须是**音频 LoRA 与 Whisper + T2-LoRA 在相同音频上的配对差值**。

## 2. 步骤与顺序
| 步 | 内容 | 输入 → 输出 | 评估 | 状态 |
|---|---|---|---|---|
| 0 | **文本 LoRA** | train 标准转写 + 冻结 T2 → T2 同格式 JSON | devel 标准转写（C0 口径） | 先做 |
| 1 | **音频 LoRA L1** | train 干净录音 + 单人完整混响 mic 0，冻结 P2 → P2 同格式 JSON | §5 全部条件 | 第 0 步后 |
| 2 | **Whisper + T2-LoRA** | Whisper large-v3（`06f233fe…`）转写**第 1 步的同一批 train 音频**，+ 冻结 T2 → 同格式 JSON；训练设置与第 1 步相同 | 与第 1 步相同的音频、相同条件 | 与第 1 步配对 |
| L2 | 音频 LoRA 加 direct 参考 | — | — | **可选**，需另行批准 |
| L3 | 加分离后的目标路 | — | — | **推迟**到 SpatialNet 完成的 checkpoint 之后 |
- 第 0 步**只用来衡量"学习 SLURP 标注范围"带来的增益**（不经过听），不作为"音频 LLM 是否更好"的证据。
- 三步都只在 thinker 的语言模型上加 LoRA：q、k、v、o（**用正则 `model\.layers\.\d+\.self_attn\.(q_proj|k_proj|v_proj|o_proj)` 限定在 thinker 语言模型的 28 层，共 112 个模块**；音频编码器 `audio_tower` 也有 96 个同名的 q/k/v_proj，不能用简单名称匹配），r = 16，alpha = 32，dropout 0.05；音频编码器冻结，talker 关闭；bf16，梯度检查点，AdamW，学习率候选 {5e-5, 1e-4, 2e-4}（第 0 步最多 3 组；**第 1、2 步各 2 组**，取 {5e-5, 1e-4}，两步相同），余弦衰减，3% warmup，有效 batch 16，最多 3 个 epoch，seed 2026。三步使用相同的超参数候选和相同的 checkpoint 间隔。
- 训练目标：SLURP 金标生成的 JSON（transcript = SLURP 句子原文，intent，entities），只对回答部分计算损失。**第 2 步的 transcript 字段也用 SLURP 原文**，与音频 LoRA 相同（2026-11-06 决定）。

## 3. 数据

### 3.2 devel 的选择半和报告半
- **单人条件改用全部 428 条 devel 录音**（382 个句子、11 个说话人、590 个金标实体，其中 date 128 个；2026-11-06 核对）。
- 划分方法（按录音划分，同一句子的录音放在同一半）：把 devel 的 382 个 slurp_id 升序排列，`random.Random(2026).shuffle`，前 191 个 slurp_id 的全部录音为**选择半**，其余为**报告半**。按此规则核对结果：选择半 **214** 条录音，报告半 **214** 条；其中 mix_v1 的 124 条录音分别有 63 / 61 条。
- 混合条件（C4-direct、C5、c6-real-v1）沿用 c6-delta-v1 的组划分（100 个组号 `random.Random(2026).shuffle`，前 50 组选择、后 50 组报告）。两种划分独立，同一条录音可能在单人条件的选择半、而在混合条件的报告半；评估时分别报告，不混用。
- 文本条件（C0 口径）按同一 slurp_id 划分：选择半 191 句、报告半 191 句；指标同时按句子和按录音（428 条，重复句按录音加权）报告。

## 4. 主要比较与"有提升"的标准
- **主要比较**：第 1 步音频 LoRA 与第 2 步 Whisper + T2-LoRA，在**相同音频**上的配对差值（音频 LoRA − Whisper + T2-LoRA）。
- 其他比较：音频 LoRA − P2；Whisper + T2-LoRA − Whisper + T2；文本 LoRA − C0（第 0 步）。
- **配对 bootstrap**：B = 2000，`np.random.default_rng(2026)`；同一次重抽样中两条路线用同样的样本，取差值的 2.5% / 97.5% 分位数。
  - 单人条件：**录音级**，按 slurp_id 成组重抽样（同一句子的录音一起抽）；
  - 混合条件：**组级**，按夹角层分层（与 c6-real-v1 相同）。
- **"有提升"**：差值 95% 区间**下界 > 0**。选择半用来选超参数和 checkpoint（按点估计取最好）、以及决定是否进入下一步；对外的"有提升"只在**报告半**上判断。
- 主指标：binding-score-v1 的"目标至少命中一个"；混合条件另看"只含干扰"（自然夹角加权）。

## 6. 退化检查（v1 草案的项目全部保留，单人条件改为 428 条的选择半）
1. C1 的"目标至少命中一个"比 P2 低不超过 0.03；意图准确率低不超过 0.03；parse 失败不超过 2%。
2. C4-direct 不低于 P2 − 0.03。
3. c6-real-v1 主条件下加权"只含干扰"比 P2 高不超过 0.01（不拒答、拒答 A、拒答 B 都查）；C3 上"只含干扰"高不超过 0.02、"目标至少命中一个"不低于 P2 − 0.03；C5 配对翻转准确率不低于 P2。
4. C5 另一路的"只含干扰"只报告。
5. 文本 LoRA（第 0 步）和 Whisper + T2-LoRA（第 2 步）同样检查 C0 / C1 不退化（对照各自的未微调基线）。
- 退化检查用点估计（经验阈值），与"有提升"的 bootstrap 标准分开。

## 7. 停止条件
1. 训练数据中出现 devel / test 的句子、录音或说话人，或者用了 cv_dev93 / test_eval92 的 RIR → 立即停止。
2. 先导测试：batch 1 峰值显存 > 38 GB，或者按实测速度预算会超出 §8 → 停下报告。
3. 训练损失 NaN 或发散 → 作业停止，只报告原因，不改配置重交。
4. **第 0 步**：选择半上文本 LoRA − C0 的配对差值 95% 区间下界 ≤ 0 → **停止，不进入第 1、2 步**，按"LoRA 没有明显帮助"报告（2026-11-06 决定）。**例外**：如果训练损失没有下降，或者输出格式失效（例如解析失败明显增多），先报告原因，不算作无增益。
5. **第 1 步**：选择半上音频 LoRA − P2（C1）的区间下界 ≤ 0，或者没有通过 §6 → 停止，不做第 2 步之外的后续（L2 不做）；第 2 步照常做，以完成配对比较。
6. 超参数：第 0 步最多 3 组，第 1、2 步各 2 组；总 GPU 时间达到 §8 上限 → 停止。
