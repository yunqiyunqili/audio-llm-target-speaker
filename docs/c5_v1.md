# C5 v1：FaSNet-TAC + v3 极性修正 + 方向匹配选路 → Qwen P2（c5-v1；2026-11-05；规则在运行前写定，不用 C5 的测试结果调整选路）

## 范围
- 前端只用 FaSNet-TAC，使用 `data/mix_v1/separated_v1/fasnet_tac/` 中已有的输出，不重跑。不加入新前端。BLSTM+MVDR 的已有结果保留，作为 baseline，本轮不做新实验。
- 不修改 P2 prompt、评估指标（slu-score-v2、binding-score-v1）、mix_v1 或任何已有结果（v1/v2/v3、C3、C4、R1）。
- 暂不拆分 C4 的差距。

## 选路规则（与 frontend-mix-v1-eval-v3 完全相同，不再改动）
1. 极性修正：对每一路 y_k，计算 c_k = Σ_t y_k(t)·x_0(t)（零延迟，mic 0 观测）；c_k < 0 时把 y_k 取反。
2. 方向估计：`eval_frontend_mix_v1.doa`。PHAT 加权互谱，以输出路为参考，对 mic 1–5 计算，平面波模型，在水平面上以 1° 为步长搜索，频带 80–3900 Hz。
3. 选路：取让 |wrap(θ̂_k − θ_query)| 最小的一路；两路一样近时取第 0 路。θ_query = θ1，即 C3 中询问的方向。
- 实现：`scripts/sms_wsj/c5_select.py`。这个脚本**不读取**任何参考信号（direct、early、完整 image）、说话人身份或 A/B 归属。输出 `outputs/c5_v1/selection.jsonl`，只包含 key、选中的路、两路的估计方向和极性修正标记。
- 选路后的输入链路与 C4 相同：选中的那一路（已按第 1 步修正极性）→ `resample_poly(x, 2, 1)[:2T]` → 有效帧 RMS 统一到 −30 dBFS → 冻结的 P2，**不加方向说明**，因为选路已经用到了方向。解码设置与 P2 相同。

## 信息依赖审计（必须如实标注）
| 环节 | 用到的信息 | 测试时能否获得 |
|---|---|---|
| 极性修正 | 输出路、mic 0 观测 | 能 |
| 方向估计 | 输出路、6 麦观测、阵列几何（麦克风坐标，取自 `sms_wsj.json`） | 能。前提是阵列几何已知，实际使用时就是自己阵列的已知参数 |
| mic 0 方位的参考方向 | 阵列几何 | 能 |
| **θ_query = θ1** | **由仿真中目标声源位置算出的真实方位**（`source_position`） | **不能**。这是 oracle 方向信息。按 `docs/conditions.md`，C5 的定义就是"真实方位选流"；用估计方位的是 C6 |
| 参考信号、说话人身份 | 不使用 | — |
| 规则的设计过程 | 极性修正是看过 mix_v1 结果之后才提出的（见 frontend-mix-v1-eval-v3） | 存在事后设计的风险。cv_dev93 的外部核查结果是 1.00 |
| 进入 C5 的门控 | 门控用的准确率是用 direct 参考算出来的，这只是评估，没有参与选路 | — |

**结论**：C5 依赖 oracle 目标方位，**不能描述为可以完全部署（fully deployable）**，只能称为"给定真实目标方位时的选路条件"。

## 评估（指标和样本范围与 C4 相同）
- 200 个样本（100 组 × 2 个互换样本），s1 的目标是 A，s2 的目标是 B，按每个样本自己的配对计算 D_T 和 D_I。
- 指标：四类比例、目标至少命中一个、目标全部命中、配对翻转准确率、M（与任一说话人 WER < 0.5）、U（和两句都无关）、解析失败、拒绝执行。实现直接调用 `eval_c4_v1.score` 和 `summ`，不改动。
- 对照：C3（22014089）、C4 FaSNet-TAC（22014545）、C4-direct（22015148）、R1（22014155）。
- 分层：夹角（[0,15) 单独报告）、T60、有效重叠比例、完整 image SIR。
- 选路是否正确：以 direct 参考匹配（v2 的 `ref_stream_direct`）为标准判断。这一步只在评估时使用，不参与选路。
- 额外报告：
  - 选路正确、但下游失败（"两者都不含"或"只含干扰"）的样本清单；
  - 选路正确和选路错误两组样本分别的下游表现；如果选路错误的样本少于 5 个，只列出，不计算比例；
  - 一致性检查：选中的路与 C4 相同的样本，Qwen 的输入只差符号，而 log-mel 特征对符号不敏感，所以 C5 和 C4 的原始输出预期相同。报告完全相同的条数。

## 描述性判断（事先写定；经验值，不是显著性检验；a = 目标至少命中一个）
- |a(C5) − a(C4 FaSNet)| ≤ 0.05：判为"**C5 选路与参考匹配选路的下游效果相当**"。
- a(C5) − a(C3) ≥ 0.15：判为"**在给定真实方位的前提下，分离 + 选路相对 C3 有帮助**"。
- a(C4-direct) − a(C5) ≥ 0.10：判为"**选路之后，分离相关的退化仍是瓶颈**"。这时按计划再考虑独立的分离质量诊断，本轮不做。
- 对 C4 差距的已有结论，只限定为"分离相关的退化是重要的性能瓶颈"，不判断残留干扰和分离失真各自的贡献。

> **C5 依赖 oracle 目标方位（θ_query = 真实 θ1），不能描述为可以完全部署。** 极性修正是看过 mix_v1 结果之后才提出的；cv_dev93 的外部核查是 1.00。
- 运行记录：
  - 选路：srun 22015334（<CPU_PARTITION>，tfgridnet 环境），结果在 `outputs/c5_v1/selection.jsonl`。与 eval v3 的选路结果比较：选中的路 200/200 相同，估计方向 200/200 相同。
  - CPU dry-run：srun 22015335。
  - GPU 作业 22015337：<NODE>，15:07:35–15:12:42，退出码 0，MaxRSS 26.6 GB。作业记录的 commit 是 `2b5ba34`，没有未提交的依赖文件；选路文件的 sha256 记在 `config.json`。

### 选路
- 以 direct 参考匹配为标准：198/200 选对。不含 [0,15) 的 150 个样本全部选对。
- 选错的 2 个都在 [0,15) 层：g006_s1 和 g074_s1，两人夹角只有 1–2°。这 2 个的下游结果都是"两者都不含"。
- 与 C4 的一致性：198/200 个样本选到了同一路；这 198 个样本的 Qwen 原始输出 **198/198 完全相同**，这与 log-mel 特征对符号不敏感的预期一致。
- 选对的 198 个样本：目标至少命中一个 0.399，只含目标 0.343，只含干扰 0.010，两者都不含 0.646。
- 选错的只有 2 个，按规则只列出，不计算比例。

### 选路正确、但下游失败的样本
- 共 130 个：两者都不含 128 个，只含干扰 2 个。其中 M = 46（转写与某个说话人接近），U = 80（和两句都无关）。完整清单在 `eval_c5_v1.json` 的 `selection_correct_but_downstream_failed.keys`。
- 说明选路基本正确之后，下游仍有约 65% 的样本失败。瓶颈不在选路。

### 描述性判断（冻结规则）
| 规则 | 数值 | 结果 |
|---|---|---|
| \|a(C5) − a(C4 FaSNet)\| ≤ 0.05 | 0.000 | **C5 选路与参考匹配选路的下游效果相当** |
| a(C5) − a(C3) ≥ 0.15 | +0.270 | **给定真实方位时，分离 + 选路相对 C3 有帮助** |
| a(C4-direct) − a(C5) ≥ 0.10 | +0.275 | **选路之后，分离相关的退化仍是瓶颈** |

- 结论限定为：分离相关的退化是重要的性能瓶颈。**不判断残留干扰和分离失真各自的贡献**，C4 的差距本轮没有进一步拆分。
- 按事先的约定，"选路基本正确，但下游仍明显不如 C4-direct"已经成立，所以下一步可以考虑独立的分离质量诊断。本轮没有做。
