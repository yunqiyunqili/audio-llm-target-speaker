# C5 v1: FaSNet-TAC + v3 polarity correction + direction-matched stream selection → Qwen P2 (c5-v1; 2026-11-05; rules written before the run; stream selection is not adjusted using C5 test results)

## Scope
- The front end is FaSNet-TAC only, using the existing outputs in `data/mix_v1/separated_v1/fasnet_tac/`, not rerun. No new front end is added. The existing BLSTM+MVDR results are kept as a baseline; no new experiments in this round.
- The P2 prompt, evaluation metrics (slu-score-v2, binding-score-v1), mix_v1 and all existing results (v1/v2/v3, C3, C4, R1) are not changed.
- The C4 gap is not decomposed for now.

## Stream-selection rule (exactly the same as frontend-mix-v1-eval-v3, not changed again)
1. Polarity correction: for each stream y_k, compute c_k = Σ_t y_k(t)·x_0(t) (zero lag, mic 0 observation); if c_k < 0, invert y_k.
2. Direction estimation: `eval_frontend_mix_v1.doa`. PHAT-weighted cross-spectra with the output stream as reference, computed for mics 1–5, plane-wave model, searched on the horizontal plane in 1° steps, band 80–3900 Hz.
3. Selection: take the stream minimising |wrap(θ̂_k − θ_query)|; stream 0 if both are equally close. θ_query = θ1, i.e. the direction queried in C3.
- Implementation: `scripts/sms_wsj/c5_select.py`. This script **reads no** reference signals (direct, early, full image), speaker identity or A/B assignment. It outputs `outputs/c5_v1/selection.jsonl`, containing only the key, the selected stream, the estimated directions of both streams and the polarity-correction flags.
- After selection, the input chain is the same as C4: the selected stream (polarity already corrected per step 1) → `resample_poly(x, 2, 1)[:2T]` → active-frame RMS normalised to −30 dBFS → frozen P2, **without the direction instruction**, because stream selection has already used the direction. Decoding settings as for P2.

## Information-dependency audit (must be labelled truthfully)
| Stage | Information used | Available at test time? |
|---|---|---|
| Polarity correction | output streams, mic 0 observation | yes |
| Direction estimation | output streams, 6-mic observation, array geometry (microphone coordinates, from `sms_wsj.json`) | yes, provided the array geometry is known; in real use these are the known parameters of one's own array |
| Reference direction of the mic 0 azimuth | array geometry | yes |
| **θ_query = θ1** | **the true azimuth computed from the simulated target source position** (`source_position`) | **no**. This is oracle direction information. Per `docs/conditions.md`, C5 is defined as "stream selection by true azimuth"; using an estimated azimuth is C6 |
| Reference signals, speaker identity | not used | — |
| Design process of the rule | polarity correction was proposed only after the mix_v1 results had been seen (see frontend-mix-v1-eval-v3) | risk of post-hoc design exists. The external check on cv_dev93 gives 1.00 |
| Gate for entering C5 | the accuracy used by the gate is computed with the direct references; this is evaluation only and takes no part in stream selection | — |

**Conclusion**: C5 depends on the oracle target azimuth and **cannot be described as fully deployable**; it can only be called "the stream-selection condition given the true target azimuth".

## Evaluation (metrics and sample scope the same as C4)
- 200 samples (100 groups × 2 swapped samples); the target of s1 is A, of s2 is B; D_T and D_I computed from each sample's own pair.
- Metrics: the four class proportions, target-any, all target values hit, pair-flip accuracy, M (WER < 0.5 against either talker), U (unrelated to both sentences), parse failures, refusals. The implementation calls `eval_c4_v1.score` and `summ` directly, unchanged.
- Controls: C3 (22014089), C4 FaSNet-TAC (22014545), C4-direct (22015148), R1 (22014155).
- Strata: angle ([0,15) reported separately), T60, active overlap ratio, full-image SIR.
- Whether stream selection is correct: judged against direct-reference matching (`ref_stream_direct` of v2). This step is used only in evaluation and takes no part in stream selection.
- Additionally reported:
  - the list of samples with correct stream selection but downstream failure ("neither" or "interferer only");
  - the downstream performance of the correctly and incorrectly selected groups separately; if fewer than 5 samples are incorrectly selected, only list them without computing proportions;
  - consistency check: for samples whose selected stream is the same as C4, the Qwen inputs differ only in sign, and log-mel features are insensitive to sign, so the raw outputs of C5 and C4 are expected to be identical. Report the number of exactly identical items.

## Descriptive judgements (written in advance; empirical, not significance tests; a = target-any)
- |a(C5) − a(C4 FaSNet)| ≤ 0.05: judged "**C5 stream selection gives downstream results comparable to reference-matched stream selection**".
- a(C5) − a(C3) ≥ 0.15: judged "**given the true azimuth, separation + stream selection helps relative to C3**".
- a(C4-direct) − a(C5) ≥ 0.10: judged "**after stream selection, separation-related degradation is still the bottleneck**". In that case an independent separation-quality diagnosis is to be considered as planned; not done in this round.
- The existing conclusion about the C4 gap is limited to "separation-related degradation is an important performance bottleneck", without judging the separate contributions of residual interference and separation distortion.

## BLSTM+MVDR (recorded only, no new experiments)
- Direction-matching accuracy: 0.713 on mix_v1 (excluding [0,15)), 0.957 on the 50 cv_dev93 groups. Direct-sound SI-SDRi: 1.72 dB on mix_v1, 4.17 dB on the 50 cv_dev93 groups.
- The two datasets behave differently; **the cause has not been found, and without further evidence it is not attributed to any specific cause**.

### Stream selection
- Against direct-reference matching: 198/200 selected correctly. All 150 samples excluding [0,15) are selected correctly.
- The 2 wrong selections are both in the [0,15) stratum: g006_s1 and g074_s1, where the two talkers are only 1–2° apart. The downstream result of these 2 is "neither" in both cases.
- Consistency with C4: 198/200 samples selected the same stream; for these 198 samples, the raw Qwen outputs are **198/198 exactly identical**, consistent with the expectation that log-mel features are insensitive to sign.
- The 198 correctly selected samples: target-any 0.399, target only 0.343, interferer only 0.010, neither 0.646.
- There are only 2 wrong selections, so by the rule they are only listed, without computing proportions.

### Samples with correct stream selection but downstream failure
- 130 in total: 128 neither, 2 interferer only. Of these, M = 46 (transcript close to some talker), U = 80 (unrelated to both sentences). The complete list is in `selection_correct_but_downstream_failed.keys` of `eval_c5_v1.json`.
- This shows that once stream selection is essentially correct, about 65% of samples still fail downstream. The bottleneck is not stream selection.
