# Pipeline and model invocation (only what actually exists; updated 2026-11-05)

Parts marked "**not implemented**" currently have no code and no results. All GPU and heavy CPU tasks are submitted via sbatch or srun (account <SLURM_ACCOUNT>).

## 0. Overall pipeline (target) and current status
```
SLURP 近讲语音 ──(配对规则 + 说话人划分)──> 句子对 ──(SMS-WSJ 6 麦 RIR 空间化，8 kHz)──> 2 人空间混合
   ├─ 条件 C0–C7（docs/conditions.md）
   ├─ 分离前端（BLSTM+MVDR / FaSNet-TAC / ...）──> 分离后的语音 ──> Qwen2.5-Omni ──> 意图 / 实体
   └─ 直接把混合语音送给 Qwen2.5-Omni（不经过分离）──> 意图 / 实体
```
(The diagram is kept verbatim from the Chinese original. In English: SLURP close-talk speech → sentence pairs (pairing rules + speaker split) → two-talker spatial mixtures (spatialised with SMS-WSJ multichannel RIRs); branches: the experimental conditions (docs/conditions.md); a separation front end (BLSTM+MVDR / FaSNet-TAC / ...) → separated speech → the audio LLM → intent / entities; or the mixture sent directly to the audio LLM without separation → intent / entities.)

## 2. Pairing and splits
- Pairing rule: same split, same intent, same non-empty multiset of entity types, different entity values, different speakers. Implementation in `scripts/slurp/make_slurp_speaker_heldout.py: pairs_in_split`.
  - From v2 on, grouping uses scenario_action; the early statistics scripts used the `intent` field of the jsonl, see Section 6.
- Formal version: `scripts/slurp/make_slurp_split_v2.py` → on shared storage `data/slurp/manifests/split_v2_seed2026/`, `configs/slurp_split_v2_seed2026.json`, `results/slurp/split_v2_stats.json`. The old `heldout_seed2026/` is deprecated (see docs/provenance.md).
- Statistics scripts (all run with `envs/qwen_omni/bin/python -I` on <CPU_PARTITION> via srun):
  - `scripts/slurp/make_slurp_speaker_heldout.py`: the seed2026 version holding out test only (list generated, on shared storage).
  - `scripts/slurp/compare_slurp_speaker_splits.py`: comparison of test 20/30/40%, results `results/slurp/split_comparison.json`.
  - `scripts/slurp/compare_slurp_split_trainsent_devel.py`: the scheme with devel using train sentences only, results `results/slurp/split_trainsent_devel_f0.4.json`.
  - `scripts/slurp/compare_slurp_devel_mixed.py`: devel = official devel sentences + 25/30/35/40% held out from train, results `results/slurp/split_devel_mixed_f0.4.json`.
- Number of pairs with each recording used at most 3 times: solved exactly by 0/1 integer programming (`scipy.optimize.milp`).

## 4. Qwen2.5-Omni-7B
- Environment: `envs/qwen_omni` (→ <SHARED_ROOT>/envs/qwen_omni), Python 3.10.22, torch 2.6.0+cu124, torchaudio 2.6.0+cu124, torchvision 0.21.0+cu124, transformers 4.52.4, accelerate 1.7.0, qwen-omni-utils 0.0.8. Full dependencies in `docs/env_qwen_omni.txt`, environment build script `scripts/qwen/build_env_qwen_omni.sh`. torchvision was installed later, because the processor loads the video processor.
- Weights: commit ae9e1690543ffd5c0221dc27f79834d0294cba00, local snapshot directory `checkpoints/hf/hub/models--Qwen--Qwen2.5-Omni-7B/snapshots/ae9e1690…`.
- Invocation:
```python
model_dir = $HF_HOME/hub/models--Qwen--Qwen2.5-Omni-7B/snapshots/<commit>    # 必须用本地目录，见下方注意
model = Qwen2_5OmniForConditionalGeneration.from_pretrained(model_dir, torch_dtype=torch.bfloat16,
            device_map='cuda', attn_implementation='sdpa', local_files_only=True)
model.disable_talker()                                    # 只输出文本
processor = Qwen2_5OmniProcessor.from_pretrained(model_dir, local_files_only=True)
conv = [system: Qwen 默认 system prompt, user: [audio, text prompt]]
text = processor.apply_chat_template(conv, add_generation_prompt=True, tokenize=False)
batch = processor(text=text, audio=[wav_16k_float32_mono], sampling_rate=16000, return_tensors='pt', padding=True)
ids = model.generate(**batch, return_audio=False, thinker_max_new_tokens=N, do_sample=False, use_audio_in_video=False)
out = processor.batch_decode(ids[:, batch['input_ids'].shape[1]:], skip_special_tokens=True)[0]
```
  (Comments in the code above: "must use the local directory, see the notes below"; "text output only"; "Qwen's default system prompt".)
- Environment variables: `HF_HOME=<SHARED_ROOT>/checkpoints/hf`, `HF_HUB_OFFLINE=1`, `TRANSFORMERS_OFFLINE=1`, `PYTHONNOUSERSITE=1`.
- Input: 16 kHz mono float32, converted by the WhisperFeatureExtractor into 128-dim mel features. 2.432 s of audio gives `input_features` of [1,128,30000] (padded to 30 s).
- 8 kHz version (C1b): scipy `resample_poly` first 1/2 then 2/1, truncated back to the original length, then input as 16 kHz.
- Notes (found by measurement):
  1. When loading with a repo id plus revision, transformers 4.52.4 does not use the given revision when looking up `spk_dict.pt`, and offline there is no `refs/main`, so it fails (job 21999394). Solved by loading from the local directory.
  2. Without torchvision, loading the processor raises an ImportError (job 21999584).
- Scripts:
  - single-item transcription: `scripts/qwen/qwen_omni_single.py` + `.sbatch` (<GPU_PARTITION> / 1×A100-40GB / 4 CPU / 48 GB / 30 min).
  - CPU pre-check (no weights loaded): `scripts/qwen/qwen_omni_precheck.py`.
  - structured SLU: `scripts/qwen/qwen_omni_c1_semantic.py` + `.sbatch` (job 22010083); offline rescoring `scripts/qwen/rescore_c1_semantic.py RUN_DIR`.
- Measured results (job 22003339, A100-PCIE-40GB, SLURP test slurp_id 0, 2.432 s, reference "wake me up at five am this week"):

## 5. Evaluation
- Separation: PIT SI-SDR / SI-SDRi, reusing the implementation in the original training code.
- SLU: parsing, normalisation and scoring are in `scripts/qwen/slu_normalize.py` (intent accuracy, entity P/R/F1, WER after normalisation); rules in `docs/c1_semantic_plan.md`. SLURP's official SLU-F1 is **not implemented**.

## 6. Known issues
- The `intent` field of the SLURP jsonl disagrees with `scenario_action` for 229 sentences. The C1 semantic test uses scenario_action; the v2 split has switched to scenario_action; statistics before v2 (split_comparison etc.) used the `intent` field and were not recomputed.
