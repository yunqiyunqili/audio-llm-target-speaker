# Experimental conditions

Source: research plan (confirmed by the project lead on 2026-11-03). In the first round, all spatial conditions are constructed at 8 kHz, and RIRs are not regenerated.

| Condition | Input | Downstream |
|---|---|---|
| C0 | target speaker transcript (text) | text LLM |
| C1 | target clean speech, SLURP original bandwidth | Audio LLM |
| C1b | C1 downsampled to 8 kHz, then upsampled to 16 kHz | Audio LLM |
| C2 | target early-reverberation speech: convolved with the SMS-WSJ early RIR at 8 kHz, then upsampled to 16 kHz | Audio LLM |
| C3 | single-channel mixture + direction question | Audio LLM |
| C4 | separated streams + stream selection by matching against reference speech (**offline diagnosis only**) | Audio LLM |
| C5 | separated streams + stream selection by true azimuth | Audio LLM |
| C6 | separated streams + target direction given by the user (a sector or an angle with error) + stream selection by system-estimated source directions (`docs/c6_real_v1.md`) | Audio LLM |
| C7 | speech selected by C5, C6 → ASR → text | text LLM |

## Conventions
- **Reverberation loss** = metric(C1b) − metric(C2). Both go through the 8 kHz bottleneck, so the difference reflects only early reverberation, without mixing in bandwidth loss. Bandwidth loss can be computed separately as C1 − C1b.
- **Azimuths** always use the angle relative to mic 0: az_rel = wrap(az(source − array centre) − az(mic0 − array centre)), in (−180°, 180°]. Angle between the two talkers = |wrap(az1 − az0)| ∈ [0°, 180°]. Implementation in `scripts/sms_wsj/sms_wsj_geometry_stats.py`.
- Upsampling to 16 kHz is to match the WhisperFeatureExtractor of Qwen2.5-Omni (sampling_rate 16000, see `docs/log/day1_followup.md` §6). The upsampling filter has not yet been decided and must be fixed and written into the configuration.

## Definition of early for C2: following the existing SMS-WSJ data
Checked against `sms_wsj/database/utils.py: scenario_map_fn` of the official code `repos/sms_wsj` (commit `f6b94bb9`); the locally generated `early/` data were generated by `write_files.py` with default parameters, which do not override this parameter. Specific definition:
1. `rir_start` = `get_rir_start_sample(h_k)`: for each talker's 6-channel RIR, find in each channel the first sample with |h| > 0.1·max|h|, then take the minimum over the 6 channels. This is the arrival time of the direct sound.
2. `early_rir_samples` = int(8000 × 0.05) = **400 samples (50 ms)**, counted from `rir_start`. early RIR = h[0 : rir_start + 400], with the remaining positions set to zero, so it contains the propagation delay plus 50 ms after the direct sound. The tail is the rest.
3. After convolution with the source signal, align by `offset − rir_start`, then multiply by the same gain as the full image (determined by log_weights and the std of the 6-channel image, then /71).
4. C2 follows this definition: SLURP target speech downsampled to 8 kHz → convolved with the early RIR of mic 0 (channel 0) of the room → aligned per point 3 → upsampled to 16 kHz.
5. Difference from the original SMS-WSJ data: SLURP speech is not WSJ, so gain and offset must be redetermined for the new mixtures; the specific rules are to be written into the data generation script.

## Metrics (decided 2026-11-05)
### Primary metric: key entity value binding (paired experiment)
- Object: a pair = (target speaker utterance T, interferer utterance I). Under the pairing rules, the two utterances have the same intent, the same multiset of entity types, and different entity values.
- **Distinguishing entity values**: values among T's entity values but not among I's are the target's distinguishing values; the reverse are the interferer's distinguishing values. Comparison uses normalize_v2 (`docs/scoring_rules.md`).
- For each pair and each condition's output, two things are judged:
  1. whether the output contains a distinguishing entity value of the target;
  2. whether the output contains a distinguishing entity value of the interferer.
- This gives four classes: target only (correct binding), interferer only (bound to the interferer), both, neither.
- **Implementation: not implemented.** Details still undecided: whether to search within the parsed entity values or the whole output text; with several distinguishing values, whether to count by all or by any; to be written into `docs/scoring_rules.md` with a version bump at implementation time.
### Auxiliary metrics
Strict SLU entity F1, intent accuracy, transcript WER (definitions in `docs/scoring_rules.md`). Existing results are not changed.

## Difference between C6δ and C6 (2026-11-05)
- **C6δ** (`docs/c6_delta_v1.md`): adds an artificial fixed offset δ (0, ±10°, ±20°) to the **true query azimuth** of C5, used only to simulate error in the query direction. **It is not an estimated azimuth**, and does not represent the error distribution of real users or localisers.
- ~~Real C6 not yet defined~~ (wording of 2026-11-05, superseded by the next item).
- **Real C6** (frozen 2026-11-06, `docs/c6_real_v1.md`): **does not estimate the target direction from the mixture audio** (the mixture audio itself cannot tell whom the user wants to hear). The target direction is provided by the user; the system estimates the source direction of each separated stream with the `doa` of v3 and takes the stream closest to the user's direction. User input is simulated in two ways:
  - **C6-sector**: the user only gives the sector containing the target (relative to mic 0, with the mic 0 direction as a sector centre); the query direction is the sector centre; the main result uses 8 sectors. When both talkers are in the same sector, the direction is "indistinguishable" and stream selection does not count as correct.
  - **C6-noise**: query direction = θ1 + Gaussian error (σ = 5°, 10°, 15°, sampled per group, 10 repetitions); the main result is σ = 10°.
- C6δ is kept, as a sensitivity analysis only.
